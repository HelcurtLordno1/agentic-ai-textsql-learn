# V5: recover semantic information without losing bounded question-first execution

V4 is frozen on remote branch `v4_research_best`, commit `4395e4a`; development proceeds
on `v5_research_upgrade`. The canonical ledger owns the gates below. This is a plan
for implementation and validation, not a claim of improved benchmark accuracy.

## Observed gaps and information flow

V4 removes the LLM plan but passes a neutral lookup plan into retrieval. A1 gets schema
and a glossary, with no independently expressed requested population, entity grain,
output positions, aggregation or ranking. CPU ranking contracts cover only a narrow
single-source edit and were eligible zero times. More agents alone do not fix this.

Eight Olist failures occur before generation: the linker renders a fallback column but
does not put that column into `selected_columns`; PK-free views then fail in the stricter
evidence builder. A Spider saved CTE is rejected because flat alias resolution mistakes
a derived field for a physical column. Another read question is blocked by a metadata
field containing the word create. The remaining errors require intent/ownership/grain
information, not removal of the safety policy. Semantic outcome remains unverified
until measured on new inference, and old gold-aware cases are diagnostic regressions.

The intent stage sees the question and schema/domain evidence before any candidate SQL.
Its fields must cite actual catalog columns and verbatim question spans. This checks
provenance, not semantic truth. Invalid intent is discarded with an explicit trace
reason; SQL generation can continue within the remaining budget. Generation remains
grounded in the original question, not compelled to follow a model hypothesis.

## Ordered gates

1. **G1: mechanical boundaries.** Reproduce old saved-context failures without a model;
   fix context/render/evidence consistency with bounded packing, CTE/subquery/alias
   scopes and metadata read intent. Test renamed/composite/PK-free schemas, negative
   unknown/ambiguous columns, correlated queries and actual write requests. Run
   `make check` before closing this engineering gate.
2. **G2: semantic intent channel.** Add typed bounded intent contracts, independent
   pre-draft extraction, span/column validation, advisory prompt handoff and trace.
   Retain request cap3 including retries and deadline180s on the authorized profile.
   Intent + draft leaves at most one repair; invalid intent/retries cannot multiply
   calls. Freeze an explicit `intent-grounded` variant and a no-intent control.
   Improve grain/output/aggregation instructions and domain definitions without case-ID
   rules or gold/runtime imports. Validate full fake-provider flows and `make check`.
3. **G3: handoff.** Replay saved failure contexts/SQL read-only, compare old/new policy
   on saved candidates, validate source/evaluation boundaries and command entrypoints.
   Provide fresh-checkpoint tmux and Administrator 450 MHz commands only after coding
   and checks finish. Preserve all V4 checkpoints, reports and stop evidence.

## Acceptance and research boundary

Engineering acceptance requires consistent bounded context, correct lexical scopes,
typed intent with evidence provenance, bounded failure paths and passing checks. It
does not require tests to assert a fresh model will answer correctly. Synthetic and
renamed fixtures test the same failure families without copying raw benchmark data.
Saved real-case replay stays in ignored artifacts. Model-based tests, if run, must use
the guarded wrapper with batch1, unload, cooldown60s, continuous Windows/WSL monitoring
and verified clock cap. No benchmark may start before all code is finished.

Full Spider/Olist runs must create new identities/paths and retain every case. Measure
first draft, final, candidate-pool oracle, paired gains/losses, language/DB/difficulty,
latency including intent cost and resources. Run a matched safe P6 control separately.
Neither zero mechanical failures nor a better diagnostic replay establishes accuracy
gains, unseen-schema generalization, or promotion; research remains IN_PROGRESS.
