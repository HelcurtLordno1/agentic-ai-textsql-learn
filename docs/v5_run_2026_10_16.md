## Vì sao sửa các phần này

Luồng cũ bỏ LLM plan, nên generation không có kênh intent độc lập để giữ population,
grain và output/ranking requirements. Repair contract hẹp và coverage thực tế bằng0
không bù được khoảng trống này. Tám lỗi Olist được tái lập trực tiếp là lỗi truyền
selected columns của view; CTE bị reject vì flat alias scope, và router nhầm metadata
"create dates" thành write. Các lỗi ngữ nghĩa còn lại cần inference mới để kiểm chứng.

Luồng V5: **question → router → retrieval → consistent schema evidence → independent
typed intent → SQL draft → scope policy/read-only execution → bounded repair/selection**.
Intent được kiểm span/column provenance nhưng vẫn là model hypothesis; nó không được
authorize SQL hoặc semantic rewrite tùy ý. `intent-grounded` có intent; `intent-no-plan`
giữ cùng hướng dẫn nhưng bỏ lượt intent để ablate. P6 vẫn là default và có control riêng.

Giữ model/context/deadline/request và các giới hạn RAM/swap/VRAM/nhiệt/power:
tối đa3 generation HTTP attempts gồm retries, context4096, input2800/output768,
intent output≤512, case180s,GPU41layers; cap mới700MHz theo yêu cầu ngày16/10.
Optional intent chỉ có1 HTTP attempt để giữ ngân sách draft;
invalid/overbudget intent bị bỏ với trace rõ. Benchmarks yêu cầu grounding index để
không âm thầm chuyển thành full-catalog run khi thiếu index.

## WSL — chạy mới toàn bộ, rồi attach

Nguồn/model/index/data phải giữ nguyên trong suốt run/resume. Tên dưới đây dành riêng
cho source/profile700MHz mới; không resume phiên450MHz hoặc
`a1-startupfix450-20261007`, không trộn với checkpoint V4.

```bash
cd '/mnt/d/desktop_informations/vnpt ai/agentic_text_to_sql'
uv run --frozen --extra ui --group dev python -m scripts.tmux_benchmarks run \
  --name v5-intent700-20261016 --variant intent-grounded \
  --profile qwen14b-16gb-clock-capped-700 \
  --models-dir /mnt/c/Users/ADMIN/.ollama/models
tmux attach -t v5-intent700-20261016
```

Harness tự chạy1pilot Spider và1pilot Olist, kiểm executable result/clock/resource,
rồi Spider còn lại và Olist còn lại, tuần tự. Không có tổng max-batches nên không cần
bấm resume giữa từng case. Batch1, unload và **cooldown60giây mỗi batch**, sampling0,5s,
continuous Windows+WSL monitoring. Tổng wall/case lớn hơn60s vì còn inference/setup.
Limits giữ RAM≥8GiB,swap<0,25GiB,VRAM<14GiB,temp<68°C,power<70W,clock≤700MHz.
Source/config/backend/model/data/index được pin. Ctrl+b rồi d để detach, workload vẫn chạy.

```bash
uv run --frozen --extra ui --group dev python -m scripts.tmux_benchmarks status --name v5-intent700-20261016
# Yêu cầu pause sau checkpoint, unload và cooldown:
uv run --frozen --extra ui --group dev python -m scripts.tmux_benchmarks pause --name v5-intent700-20261016
# Chỉ resume sau PAUSED sạch:
uv run --frozen --extra ui --group dev python -m scripts.tmux_benchmarks resume --name v5-intent700-20261016
tmux attach -t v5-intent700-20261016
```

Sau shutdown/reboot bất ngờ: stale jobs phải absent, idle sample an toàn, cap700MHz
được áp lại; dùng `resume --name v5-intent700-20261016 --recovery-pilot`, đợi PAUSED
sạch rồi resume bình thường. Sensor/resource stop vẫn latched, giữ reason/peak và
không tự retry/override. Cần remediation thực trước khi cân nhắc một pilot khác.
